# 维修上门通知生成 SOP

根据报修数据表，为每户业主生成标准格式的维修上门通知 Word 文档。

## 输入数据格式

用户提供的数据应包含以下字段（从台账或表格中提取）：
- 楼栋号、室号、房修工程师/报修人姓名、联系电话
- 报修问题详述
- 责任单位、工种、报修日期

## 输出格式标准

每户一条独立通知，之间用分页符分隔。每条通知格式如下：

```
[责任单位/项目名称]项目维修上门通知

尊敬的X栋XXX室业主，您好！
您家之前报修的[具体报修问题]问题，我们已安排维修负责人，将于明天（X月X日）下午上门处理。
烦请根据您的实际情况回复以下任一选项：
如您当天在家，请回复"在家"，以便我们合理安排负责人上门时间；
如您当天不在家，但门锁密码未更改，请直接回复密码，我们将安排负责人上门作业；
如您当天确实不便，可不回复或回复"不方便"，后续我们重新安排维修时间后将第一时间再通知您，感谢您的耐心等待。
维修负责人：[称呼/姓名] 联系电话：[电话]
如需确认具体上门时间，可明天直接致电[称呼/姓名]沟通。
感谢您的支持与理解，我们将竭诚为您服务！

璀璨云著维保中心
2026年X月X日
```

## 生成流程（每户文档模式）

1. 确认任务参数：
   - 责任单位/项目名称（如：星网天合智能家居、恺云居玄关柜、圣象地板等）
   - 上门日期（明天 = 当前日期 + 1天）
   - 维修负责人姓名和电话（如：金总 138****0000、张师傅 138****0000）
   - 报修数据（楼栋、房号、问题描述、报修日期）

2. 使用 `scripts/generate_notifications.js` 脚本生成 docx 文件：
   - 修改脚本中的 `repairs` 数组和 `contactName`、`contactTel`、`projectName` 等变量
   - 运行：`node generate_notifications.js`
   - 输出文件：`[项目名称]维修上门通知_X月X日.docx`

3. 将生成的文件交付给用户。

## Word 文档格式规范

- 字体：微软雅黑
- 标题：加粗，字号 32，居中对齐
- 正文：字号 24，左对齐
- 页面：A4，边距 1440 twips
- 每户通知之间：分页符分隔

## 注意事项

- 报修问题描述直接使用用户提供原文，不要改写
- 如果业主电话有两个（如俞岩 138****0000 / 138****0000），统一使用第一个
- 业主姓名中的姓氏（如"高""王"），通知中直接使用原名即可
- 日期格式：正文中"明天（M月D日）"，落款用"YYYY年M月D日"

## 朋友圈海报模式（新场景）

用于"以单户/单元楼通知 + 提供一张二维码海报原图"为输入，生成可发朋友圈/楼栋群的长图海报。

### 触发信号

用户措辞包含「**做图片通知**」「**发朋友圈**」「**做个海报**」「**图片样式通知**」「**附加二维码**」等，并 @image#1 提供了一张二维码/海报原图。

### 海报三段结构（自上而下）

1. **顶部条** —— 深色背景（建议 `#182030` 深蓝灰），底部一条 6px 黄色装饰线（`#FFC440`），居中放置白色微软雅黑 Bold 文字抬头，**只写送达户**（如「尊敬的1栋01、06户型业主，您好！」），字号 60-70，居中。
2. **正文区** —— 浅灰背景（`#F5F6F8`），通知文案：标题居中加粗 50-54px，正文 36-40px 黑色，节段之间空一行；落款用小字号居中（可选「璀璨云著维保中心」+ 日期）。
3. **底部二维码区** —— 用户原图**完整保留**，不裁剪不缩放任何字符，直接 `paste` 在底部；二维码可正常扫描视为合格。

### Python 生成模板（依赖：Pillow）

输出文件名规则：`[项目名称]通知_朋友圈海报_[送达单元].jpg`

关键尺寸（按原二维码宽度自适应）：
- 总宽 = `qr_img.width`（原图宽）
- 顶部条高 ≈ 200px（不宜<160，否则抬头被截）
- 装饰黄线 6px
- 正文行高 ≈ `字号 × 1.6`，行间距 ≈ `字号 × 0.6`
- 整体输出比 ≈ 9:16 至 3:4，适合朋友圈刷屏

### 常见坑
1. **抬头被截** → 顶部条高度按 `img.height × 0.13` 起步；字号取 `header_h × 0.40`，超长抬头分两行。
2. **二维码模糊/被压** → 必须原图 `paste`，**不可缩放**；如必须缩放，需先验 QRCode 内容是否仍可识别。
3. **文字避头** → Pillow `textbbox` 计算居中时记得减去 bbox 偏移（`-bbox[0]` / `-bbox[1]`），否则字偏右下。
4. **emoji/空格截字** → 中文字符串里含 `（`、`，` 等全角符号没问题；避免用 f-string 的 `<` `>`（沙箱下被 shell 当重定向）。
5. **使用 Pillow 时务必 `PYTHONIOENCODING=utf-8`**，否则中文路径报错。
6. **每户文档模式脚本只适用于 docx 输出**，朋友圈海报模式用 Pillow 一脚本一行搞定，不要复用 docx 脚本。

### 参考生成步骤（Python heredoc）

```python
from PIL import Image, ImageDraw, ImageFont
qr = Image.open(r'<原二维码图路径>').convert('RGB')
W, QH = qr.size
header_h, body_h = 200, 800
new = Image.new('RGB', (W, header_h + body_h + QH), (245, 246, 248))
draw = ImageDraw.Draw(new)
# 顶部条
draw.rectangle([0, 0, W, header_h], fill=(24, 32, 44))
f = ImageFont.truetype(r'C:/Windows/Fonts/msyhbd.ttc', 66)
draw.text(((W-f.getbbox('抬头')[2])//2, 60), '抬头', font=f, fill=(255,255,255))
draw.rectangle([0, header_h-6, W, header_h], fill=(255, 196, 64))
# 正文（多行居中）
# 底部
new.paste(qr, (0, header_h + body_h))
new.save(r'<输出路径>', quality=95)
```

### 一次性封装
- 朋友圈海报输出文件名应为`[项目名称]通知_朋友圈海报_[送达单元].jpg`
- 输出后必须 `present_files` 展示，确认抬头不被截 + 二维码完整可扫
- 修抬头/正文/装饰色都是改代码重跑，不允许手动覆盖原图

## 数据源：从报修台账筛选未维修条目（新场景）

当用户说"针对台账里 XX 单位未维修的发通知"，需要先从台账筛选再生成。

### 台账结构（璀璨云著A地块「台账」sheet，14列）
列序：1项目 2报修渠道 3楼栋号 4室号 5报修人姓名 6联系电话 7报修问题详述 8房修工程师 9责任单位 10工种 11报修日期 12是否完工 13完成时间 14备注

### 筛选规则
- 未维修 = `责任单位(col9)` 含目标单位（如"圣象"）且 `是否完工(col12)` ≠ "是"
- 不要依赖单元格填充色判定完工状态（read_only 模式读不到 fill）

### Python 读取要点（已踩坑，务必照做）
1. **openpyxl 必须用 `ws.iter_rows(min_row=2, values_only=True)` 逐行遍历**；read_only 模式下逐格 `ws.cell(row=,column=)` 随机访问在万行级大表上会**静默 exit 1 无输出**。
2. 台账文件若在 `D:/WorkBuddyClaw/` 等工作区外，先 `cp` 到工作区临时目录再读（沙箱拦截 Python 读外部路径）。
3. 多电话取首个：`str(tel).replace('\n',' ').split()[0]`；同户号相同描述要去重。
4. 合并同户号：`(楼栋,室号)` 为 key 分组，多条问题合并为一条通知；空业主姓名/电话用通用称呼「尊敬的X栋XXX室业主」。

### 生成链路
`python(openpyxl 筛选+合并去重) -> 导出 sx_pending.json -> node(docx 包, 设 NODE_PATH) 读 JSON 生成 docx`

- node require('docx') 需 `NODE_PATH=C:/ProgramData/WorkBuddy/chromium-env/6s4p0b/.workbuddy/binaries/node/workspace/node_modules`
- 告知式通知模板（方便联系师傅/不方便忽略）参考「和乐入户门」精简结构；密码二选一参考标准 SOP
- 输出后必须 `present_files` 展示校验
